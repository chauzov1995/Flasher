# Тест Green2: регистрация платы

Это первый этап заводского теста, по существующей схеме `testteplica`: плата сама
отправляет конфигурацию в `smart.giulianovars.ru`. Рабочая прошивка Green2 с общей
библиотекой `tehhclass` остаётся в Arduino-проекте. Этот отдельный скетч не запускает
рабочий контроллер, MQTT или HomeKit и не выполняет OTA.

## Что проверяет

- ESP32-C6 и flash 8 МБ; MAC Wi-Fi STA берётся из eFuse.
- SHT31 по SDA=4/SCL=5, адрес 0x44, CRC температуры и влажности.
- Выводит входное напряжение по GPIO1, состояния кнопки GPIO3, SYNC GPIO7 и
  nFAULT GPIO2/22. Напряжение информационное, без новой калибровки.
- После команды регистрации проверяет Wi-Fi, время NTP, сертификат HTTPS
  и результат записи объекта. Наличие старой конфигурации не проверяет.

GPIO18/19/20/21 постоянно LOW. Моторы не запускаются, GPIO0/ток не измеряется,
DS18B20 не проверяется. Положение привода неизвестно: в конфигурации `on: null`.
Надпись «Зарегистрировано» не означает, что моторы или все узлы платы прошли тест.

## Работа на стенде

1. Запустите **новую** сборку Flasher с поддержкой ESP32-C6. Профиль —
   **testgreen2 / Green2 · регистрация, моторы выключены**, порт вашей платы.
   Старый EXE до этой доработки не поддерживает C6. Профиль **всегда полностью стирает
   flash** перед записью, независимо от общей галочки стирания. Тест заменяет рабочую
   программу и удаляет сохранённые настройки платы.
2. После прошивки откройте монитор Flasher. Каждые 3 секунды идут `GREEN2_TEST STATUS`
   и состояние теста. При исправном SHT31 и 8 МБ будет `GREEN2_TEST READY`.
3. Для регистрации удержите **SYNC (GPIO7)** две секунды и отпустите. Это не кнопка
   BOOT и не кнопка ручного открывания на J4. При старте уже нажатая SYNC не вызывает
   регистрацию: сначала её нужно отпустить.
4. Альтернатива — закрыть монитор Flasher, открыть Arduino IDE: COM-порт платы,
   **115200 бод, New Line**, ввести `@g register` и нажать Enter. Только одна программа
   может держать COM-порт. У CP210x DTR/RTS должны быть выключены при мониторинге.
5. Успех: `GREEN2_TEST REGISTERED id=GN_<mac> child=GN_<mac>_1`.
   Flasher показывает «Зарегистрировано · моторы не проверялись».
6. После регистрации записывается **рабочая** Green2 из Arduino-проекта.
   Этот тест не скачивает её автоматически. Поддержка карточки Green2 в приложении
   и остальных сервисах — отдельный этап; успешная регистрация её не заменяет.

Команды монитора:

| Команда | Действие |
| --- | --- |
| `@g help` | Список команд |
| `@g status` | Локальные измерения и состояние |
| `@g payload` | Показать JSON будущей регистрации, без HTTP |
| `@g register` | Заново записать заводскую конфигурацию на сервер, включая существующее устройство |

Автоматических обращений к API при включении нет. Команда регистрации использует
реальный сервер, а не тестовую базу. Сборка и проверка образов устройство не регистрируют.

## Регистрация и повторные попытки

Идентификатор родителя — `GN_` + 12 строчных hex-символов MAC Wi-Fi STA, дочерний —
`GN_<mac>_1`. В JSON оба типа `green2`, владелец `0`,
`chekedprosh: false`; начальная температура 27 °C, гистерезис 1 °C.

1. После проверки платы и связи каждый вызов `@g register` или удержание SYNC
   отправляет `POST /api/app/v1.0/user/create_conf`. Предварительных GET нет.
   Существующая запись, её тип, настройки и предыдущий результат регистрации
   не блокируют отправку. Журнал попытки в NVS не используется.
2. Ответ должен быть HTTP 200 + `OK`. После записи
   `GET /api/app/v1.0/device/getConfig?id=GN_<mac>` подтверждает дочернюю запись
   типа Green2. Это проверка результата, а не условие разрешения перезаписи.
3. `POST /api/app/v1.0/device/upd_wifi2` сообщает модель `green2`, версию и Wi-Fi
   родительской платы: текущий `create_conf` сам тип родителя в БД не сохраняет.

Повторная команда после успеха, ошибки или потери ответа снова отправляет
`create_conf`. По запросу владельца стенда это заводской режим с перезаписью:
прежняя серверная конфигурация заменяется, владелец сбрасывается в `0`.
Автоматического повтора в цикле нет: один вызов команды или одно удержание SYNC —
одна попытка записи. HTTP-ошибка или неподтверждённый результат показываются как
ошибка, а не как успешная регистрация. Серверные ограничения API остаются в силе.

Версия `green2-test-1.0.1`: включено полное стирание в профиле, удалены проверка
старой записи и блокировка повторной попытки, использовавшиеся в версии 1.0.0.

## Сборка

Arduino-ESP32 **3.3.12**, ArduinoJson **7.4.3**. В IDE: **ESP32C6 Dev Module**,
**8MB**, **8M with spiffs (3MB APP/1.5MB SPIFFS)** (`default_8MB`),
**USB CDC On Boot: Disabled**. Вывод идёт через UART0 GPIO16/17, а не USB CDC.
У платы TX=GPIO16, RX=GPIO17. В `HardwareSerial::begin` аргументы идут в порядке
**RX, TX**; в скетче используются проверенные константы `RX, TX` выбранной платы.

Скопируйте `green2_wifi.example.h` в `green2_wifi.local.h`, задайте Wi-Fi 2,4 ГГц.
Локальный заголовок исключён из Git. На текущем стенде он подготовлен из настроек
существующего `teplica2_testprosh`, без вывода пароля в журнал. Пароль попадает в
скомпилированный образ: комплект предназначен для доверенного стенда.

Из корня Flasher:

```powershell
./projectsard/green2_testprosh/build-kit.ps1
python tests/Green2.Registration/run.py
dotnet run --project tests/Flasher.Checks -c Release
```

`build-kit.ps1` собирает и копирует три образа одной сборки в `projects/testgreen2`,
сохраняет SHA-256 в `build-info.json`. Скрипт использует установленный Arduino IDE CLI.
Проверка регистрации использует ArduinoJson и Windows-host компилятор установленного
Android NDK; плата, COM-порт и сервер не используются.

Версия `green2-test-1.0.2` исправляет перепутанные RX/TX в версиях 1.0.0–1.0.1.
Консоль принимает только строки команд с префиксом `@g`, игнорирует эхо служебных
сообщений и повреждённые/слишком длинные строки. Обработка входа ограничена 128 байтами
за проход цикла, поэтому непрерывные входящие данные не блокируют периодический статус.

Для новой поставки Flasher можно собрать автономную Windows x64 папку, не требующую
отдельной установки .NET на рабочем месте:

```powershell
dotnet publish src/Flasher/Flasher.csproj -c Release --self-contained true -o publish/green2
```

Карта записи: загрузчик `0x0`, таблица `0x8000`, общие начальные данные OTA
`0xe000`, приложение `0x10000`; DIO, 80 МГц, 8 МБ, esptool **5.3.1**.
Старые профили используют прежний esptool **3.1**, ESP32, 4 МБ и загрузчик `0x1000`.
`partsheme/esptool-c6.exe` взят из установленного пакета Espressif; лицензия рядом
в `esptool-c6-LICENSE`.
